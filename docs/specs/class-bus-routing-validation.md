# 类图公共主干冲突修复验收（#791）

## 范围与完成定义

修复接口继承、接口实现或普通关系共享同一个目标端口、覆盖对方线型／端点符号的问题。目标是让合法的自动关系保留正确的 UML 语义，并保留原有同类公共主干的阅读价值。

本轮按用户确认直接推进局部修复和 PR。范围以 [Issue #791](https://github.com/tt-a1i/archify/issues/791) 的复现为起点；不新增 schema、配置、关系种类，也不改共享 Router 接口。

## 实现约束

1. 主干候选仍按目标与关系种类分组，先保留原有节点障碍检查。
2. 只允许同一候选组共享端口和走廊；检查本组与完整场景中组外路线的端点间距、重叠走廊及内部交叉。
3. 有冲突时整组回退，通过现有普通路由器重新分配；仅发生回退后启用已有的独立端口模式，防止等高交错关系重新共享走廊。
4. 每轮只删除冲突组，再检查剩余主干。候选集合单调缩小，最多候选组数次回退；不增加无界重试。
5. 节点位置、文本、关系身份和方向不变。保留显式 via、侧边、直线路由及 labelAt；不增加对所有固定路线间距或任意布局成功的保证。
   空数组 `via: []` 在关系入口与省略字段统一；仅克隆需要归一化的条目，不改原始文档，非空路径仍保持显式控制。
6. 正常同类主干保留反向绘制和 source-to-target 的 data-motion-path，Focus 与独立 SVG 导出继续使用正确语义。

## 边界

- 这是主干协调与局部回退，不是通用图布局保证。不同目标的复杂交错层次仍可能被现有 crossing 约束拒绝。
- 固定几何保持原值，既有 Router 对固定与自动端点的全部间距边界不在本次修复范围。
- 自动路线允许变化；测试保护关系语义、真实冲突和作者控制，不冻结自动坐标。
- 实现与本地验收完成；维护者审查、合并、发布和安装各自独立。
